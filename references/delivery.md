# 编译与交付检查

## 编译

先检查实际可用的编译环境。支持本地 `latexmk` 时，在任务的 `report/` 内运行：

```sh
latexmk -xelatex -interaction=nonstopmode -halt-on-error main.tex
```

文科报告改为 `report.tex`。仅有 `xelatex` 时运行两遍，有交叉引用未更新则再运行必要轮次。不要为了编译默认启用 shell escape。

没有本地工具时，可使用环境提供的项目级 LaTeX 编译能力。确认它会读取项目中的字体和图片；只支持单文件预览时，应告知与完整项目的差异。不能编译时保存完整源文件和依赖，明确说明尚未验证，不声称已有最终 PDF。

## 内容与版面

- 对照要求逐项核实：任务、章节、字数或页数、格式、文件类型和附件。
- 查找示例文本、占位图、示例数据、未填个人信息和占位参考文献；结合上下文判断，不直接按关键词批量删除。
- 核对结论与证据、图表编号与正文引用、公式和文献；清理 undefined references、缺字、缺图等警告。
- 打开或渲染实际 PDF，检查封面、目录、正文与末页；有表格、代码、图片或长标题的页面应重点检查。有异常时扩大检查范围。Beamer 逐页检查可读性与溢出。
- 确认实验报告的校徽与学校匹配，文科报告严格字体模式能通过，Beamer 使用预期项目字体。

## 打包

将最终 PDF 放到任务的 `deliverables/`。需要源文件包时，将完整 `report/` 的 TeX、字体、图片、许可文件与必要说明打包；排除编译中间文件与无关的原始材料。保留任务目录里的研究或运行证据，是否随作业提交以老师要求为准。

在 `workflow.md` 记录实际验证情况和未解决项，再更新 `task.json` 阶段。交付时链接 PDF 和源文件包；存在缺口时说明它们对提交的影响。自动制作不代表已向老师或课程平台提交。
